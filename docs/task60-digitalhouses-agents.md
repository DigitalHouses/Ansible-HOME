# №60 — DigitalHouses Agents

**Назначение:** отдельная установка и приёмка штатных `digitalhouses_pve_agent` на PVE и `digitalhouses_plex_agent` + GPU Helper внутри уже развёрнутой Media VM. Запускается **после №30**, не входит в №10/№30. Самостоятельный playbook: `playbooks/digitalhouses-agents.yml`.

## Порядок запуска

1. №05 — сохранить MQTT broker, username и password в Semaphore Variable Group.
2. №10 — настроить Proxmox без установки PVE Agent.
3. №30 — установить/пересоздать медиасервер, импортировать либо создать ZFS, настроить Plex, Jellyfin, *Arr и завершить встроенную приёмку №81 **без агентов**. Эта задача закрепляет гостевой SSH ED25519 через QGA в `media80_known_hosts` у Runner.
4. №60 — выбрать `DH_AGENTS_MODE=audit` для полностью read-only наблюдения или `apply` для установки отсутствующих, согласования MQTT и запуска обоих агентов. Необязательный `DH_AGENTS_UPDATE=yes` обновляет существующие версии только до утверждённых pinned релизов (по умолчанию `no`).

№60 не перезапускает PVE/Media VM, не форматирует и не импортирует ZFS, не трогает Plex media-библиотеки, не создаёт новые аккаунты приложений. При первом запуске необходимо, чтобы №30 уже завершилась успешно.

## Технический контракт

- Читает private site и media VM manifest через прежний GitHub provisioning token №05, PVE из `/etc/digitalhouses/pve.yml` Runner. Не вводит отдельные IP или MQTT-пароли в Survey.
- PVE подключается по существующему pinned SSH ключу Runner; принадлежность VM и QGA ED25519 сверяются с сохранённым результатом №30 **до** подключения к гостю. Изменившаяся SSH-идентичность VM останавливает №60 и требует штатного №30.
- Конфигурация MQTT для PVE и Plex Agent только из `DH_MQTT_BROKER_HOST`, `DH_MQTT_USERNAME`, `DH_MQTT_PASSWORD` группы №05, порт 1883; токены и пароли не выводятся в лог.
- PVE Agent: неизменённый штатный установщик `digitalhouses_pve_agent-v0.5.75` и SHA256. Существующая более новая версия не понижается; исправная установленная версия не обновляется по умолчанию.
- Plex Agent: штатный установщик `digitalhouses_plex_agent-v0.8.5` с проверенной SHA256, отдельный GPU helper, включённый автозапуск и проверка GPU PMU. Для **первой чистой установки без старой конфигурации, BUILD_INFO и legacy-state** до запуска установщика создаётся только его собственный маркер уже несуществующей legacy MQTT-миграции. Это предотвращает ложную попытку миграции при конфиге, заранее подготовленном Ansible. Для существующих/legacy систем штатный механизм очистки не обходится. При отсутствии флага обновления существующий рабочий релиз не заменяется.
- `audit` только читает статусы, enabled-состояние и BUILD_INFO и выводит `PASS/NOT_READY` для каждого агента, без записей на хостах. После `apply` отсутствующие или неактивные агенты — ошибка приёмки №60.

**MQTT discovery:** идентификаторы `instance_id=pve` и `instance_id=plex` не меняются в ходе переноса, чтобы не переименовать существующие сущности Home Assistant. Если несколько медиасерверов публикуются в один MQTT broker, требуется отдельное согласование уникальной идентичности каждого агента; №60 не меняет её молча.

## E2E статус (11.11.2026)

Semaphore №36 `Recreate + Import` подтвердил пересоздание VM2223 и сохранение ZFS, а также настройку Plex/Jellyfin/*Arr/qBittorrent. Процесс остановился после установки Plex Agent на финальном участке официального скрипта с `no_log` и не достиг остатка №30, включая приёмку №81. Диагностика показала `BUILD_INFO`, локальный Plex token, рабочие `digitalhouses_plex_agent` и GPU helper; точная причина не подтверждена. **Перенос в №60 — изменение кода; живой E2E №60 ещё не выполнен**. Следующий шаг: №30 `Apply + Keep + Import`, затем №60 `Apply`, `DH_AGENTS_UPDATE=no`.
