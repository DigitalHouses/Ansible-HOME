# №15 — Cloudflare на объекте (HOME)

Задача управляет **одним** Cloudflare Tunnel с именем `<site-id>`
(например, `serzhan-home`), его коннектором на site Runner и
публикацией отдельных сервисов в общем Tunnel.

**Пункт «Создать PVE / File Browser» создаёт ingress-маршрут и CNAME,
а не отдельный Tunnel.** Сервисные Tunnel запрещены.

## Форма Semaphore

| Параметр | Выбор | По умолчанию |
| --- | --- | --- |
| Коннектор | Проверить / Создать / Пересоздать | Проверить |
| Публикация PVE | Пропустить / Создать маршрут | Пропустить |
| Публикация File Browser Quantum | Пропустить / Создать маршрут | Пропустить |
| Версия cloudflared | Не обновлять / Обновить | Не обновлять |

Режимы независимы от №10. «Проверить» читает состояние Tunnel и
локального сервиса, ничего не изменяя. «Создать» сохраняет уже
существующий работающий Tunnel; если Tunnel отсутствует — создаёт один
удалённо управляемый Tunnel и устанавливает коннектор на Runner.
Если Tunnel существует, но не работает и локальный коннектор
отсутствует, устанавливает коннектор с **тем же UUID**, не удаляя Tunnel.
«Пересоздать» — явно разрушительное действие: сохранение всех старых
маршрутов и существующих CNAME, проверка локального владения
коннектором, остановка коннектора, удаление старого Tunnel,
создание нового с новым UUID и токеном, восстановление маршрутов и DNS.
Cloudflare Access и данные приложений не удаляются. Ожидается
краткий перерыв удалённого доступа.

Если чужой DNS, неподдерживаемый ingress или чужой коннектор
не позволяют сохранить ресурсы, пересоздание **останавливается до удаления**.
Если старого Tunnel нет, «Пересоздать» эквивалентен созданию нового.

## Публикация сервисов

Маршруты можно добавлять независимо, после проверки существующего
здорового Tunnel, даже если для коннектора выбран режим «Проверить».

- **PVE:** `<site-id>-pve.digitalhouses.vip` → `https://<pve.ipv4>:8006`,
  проверка TLS через bootstrap CA, `noTLSVerify: false`.
- **File Browser:** `<site-id>-pve-filebrowser.digitalhouses.vip` →
  `http://<pve.ipv4>:8090`, локальный `/health=200` и обязательная
  аутентификация администрации.

Создание маршрута идемпотентно: существующий маршрут **не заменяется**.
При публикации нового маршрута Cloudflare Access обязан иметь
ограниченную email allowlist без Everyone/bypass; чужие CNAME
не захватываются. Другие ingress сохраняются без изменений.
Вход через Cloudflare Access не заменяет авторизацию самого сервиса.

Пункт «Обновить версию» использует только официальную APT версию
`cloudflared` на Runner и обновляет **только работающий управляемый
`digitalhouses-site-cloudflared.service`**. Он не меняет UUID,
настройки Tunnel, DNS, Access и данные.

## Область задачи

№10 отвечает за установку PVE/Quantum локально. №15 отвечает за
один site Tunnel, коннектор и перечисленные два публичных маршрута.
Существующие задачи №08 (проверка Semaphore) и №32 (публикация Webmin)
пока имеют собственные операции с отдельными маршрутами **того же
site Tunnel**; новых Tunnel они не создают. Перенос остальных
маршрутов в №15 не входит в эти первые пять действий.
